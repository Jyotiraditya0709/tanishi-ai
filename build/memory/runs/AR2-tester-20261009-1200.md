# AR2 · tester run

1. **What did we learn?** The Practice tier is checkable from the spec alone: counts (9 legacy + 20 new = 29), tags
   (`legacy`, `judge:llm`, `tool:*`), CEI eligibility (26 of 29), and planted-value agreement between each task's setup
   script and its verifier. End-to-end tests drive the real `run()` with scripted executors: one that does the work and
   really calls the tool, and one that gives the right answer without calling it. The second must score 0.
2. **What failed, and why?** Only lint: import order in `tests/arena/practice/test_practice_end_to_end.py` and
   `tanishi/arena/practice/checks.py` (CI's ruff wants isort order; same slip as AR1). Fixed with `ruff --fix`.
3. **Which assumption was wrong?** That the exam could be written with no implementation present. `load_practice`,
   `cei_eligible`, `needs_tool` and `PRACTICE_DIR` are an interface the exam relies on; the spec does not name them.
   If the implementer renames them, the exam breaks at import, not by a real failure.
4. **What should the next agent know?** `tests/arena/practice/` (251 tests) plus `tests/arena` (395) pass. Tool
   verifiers read a tool-call trace, so any executor for these tasks must record calls through `ToolRegistry.execute()`.
   There is no hypothesis-style property test; the invariants (never positive on failure, tool-not-called scores 0)
   are covered by parametrized cases over all 29 tasks. The red-team agent has not attacked AR2 yet.
