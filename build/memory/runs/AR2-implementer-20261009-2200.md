# AR2 · implementer run

1. **What did we learn?** The tester's commit (203c497) already held the full Practice tier, so the implementer's job
   was to check it against the live system. 10 more tool tasks now run end to end through the real runner and the real
   `ToolRegistry` (`tests/arena/practice/test_real_tools.py`), and score 1 from live tool output. Every tool task scores
   0 when a tool is really called but the answer is wrong. Before this, those 10 were only checked against hand-written
   tool output. Acceptance: 9 legacy tasks ported (3 tagged `judge:llm`, left out of CEI), 20 new tasks, 11 of the
   new ones need a tool.
2. **What failed, and why?** Nothing failed at runtime. `legacy.py` pointed to a known-bugs file that did not exist.
   It is now written (`known-bugs/ar2-system-info-no-ram.md`).
3. **Which assumption was wrong?** That the registry retries the flaky probe (the legacy benchmark said so). It does
   not, so an agent has to call it again itself. Also, `get_system_info` cannot answer the legacy RAM question.
4. **What should the next agent know?** Tool verifiers parse the `key: value` lines of `get_datetime` and
   `get_system_info`. If you change those formats, run `test_real_tools.py`. Do not import
   `tanishi.autoresearch.benchmark` in an attempt: it loads `.env`. The red-team agent has not attacked AR2 yet.
