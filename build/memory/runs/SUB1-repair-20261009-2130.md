# SUB1 · repair run (red-team fixes)

1. **What did we learn?** `events.redact()` can be reused as a secret detector: a string is secret-bearing exactly when
   redact changes it, once lone surrogates are normalised (redact rewrites those too). Applying redact only to strings
   it would change keeps the round-trip exact for every state that holds no secret. Calling `_validate` on the rebuilt
   state in `load()` turns every wrong-shaped row into one `ValueError` with a single code path.
2. **What failed, and why?** The B2/B3 fixes (unique, non-empty step ids) failed about 30 of the exam's 150 property
   seeds, because the exam generates step ids that can be empty or repeated. Both were backed out and written up in
   `open-problems/SUB1-repair-conflicts.md`. 2 red-team tests fail until the human rules.
3. **Which assumption was wrong?** That refusing secrets was the fix. The red-team report preferred refusing, but its
   test reads the stored row after a successful `save()`, so only redact-on-write passes it. Decision 0014 item 6
   records the choice.
4. **What should the next agent know?** Statuses must now be lowercase with no surrounding blanks. Secrets in state are
   stored as `[REDACTED...]`, so do not keep a key in `working` and expect it back; read keys from the environment.
   A secret-named key only has its text values redacted (`known-bugs/sub1-redteam-20261009.md`). Suite: 1196 passed,
   2 failed (B2, B3), 5 xfailed. SUB1 produces no intelligence, so there is no benchmark.
