## The four questions

1. **What did we learn?** Two of the human's decisions contradict the exam, and the exam cannot be edited in a
   repair round. For RT-3 they are the same call sequence with opposite assertions. When the red team's proof and the
   exam disagree, the conflict note is the deliverable. The right fix is still worth building next to it
   (`forecast_from_ledger`), so the human's resolution is a small change, not a new node.
2. **What failed, and why?** Nothing failed in the end. A first bulk edit script was too long for the shell parser
   and inline Python needed approval, so all edits went through the Edit tool and the timing and brute-force checks
   became permanent tests.
3. **Which assumption was wrong?** That an inverted index alone makes linking near-linear. Every step text in a
   family shares its span-name words, so plain word posting lists are as quadratic as all-pairs. Only indexing each
   text's rarest |a| - floor(0.5·|a|) words (prefix filtering, exact for Jaccard > t) makes it near-linear.
4. **What should the next agent know?** Do not wire `mastered` into any gate without also requiring
   `forecast_trusted`, until the human resolves RT-3. `nightly()` still returns a list (the exam needs it); use
   `nightly_report()` for counts. A forecast can only be trusted if it is written before the node's first outcome,
   ever. Seeds already scored can never become trusted-mastered without a reset rule.
