1. **What did we learn?**
   - An `INSERT OR REPLACE` passes its conflict policy down to the INSERTs inside a trigger. The leftover
     `goal_ancestors` row that looked like it blocked a REPLACE owner flip was replaced too, so the flip went through.
     A BEFORE INSERT check (`id exists with a different owner`) closes it, because BEFORE triggers run before REPLACE
     deletes the old row.
   - A depth check fits in a trigger without `WITH`: a goal's level is its number of `goal_ancestors` rows, and a
     subtree's height is `MAX(COUNT(*)) GROUP BY goal_id` over its members.
   - A migration test can pin the db at an older version by pointing `db.MIGRATIONS_DIR` at a temp dir that holds only
     the old files, then undoing the patch.
2. **What failed, and why?** The strict owner check on insert (part of ruling 2) was built, run, and taken out: it
   turns red-team G3 red, because G3 inserts `'USER'` by raw SQL. The 64-level cap was kept, though red-team G8
   still fails: G8 builds a 300-deep chain, and it failed before the cap as well.

   (owner on insert, the depth cap) meet red-team tests that expect the opposite. Also wrong: the red-team report's
