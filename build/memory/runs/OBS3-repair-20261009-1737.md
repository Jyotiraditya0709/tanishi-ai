The exam (`test_attribution.py`) is unchanged and passes 60/60. Rules are in decision 0011 (renamed from 0008).

1. **What did we learn?**
   - A 2x-noise rule needs a floor. Noise of 0 is common (a scorer that ignores the seed, a cached model) and it turns the bar into "> 0".
     Here the floor is 0.01 on a 0 to 1 scale. The exam's smallest real gain is 0.02, so the floor sits safely under it.
   - Pairing has to be enforced where the data is read (`seed_scores`), not only where it is planned (`interleave`). The plan was
     always paired, but crashes and partial reruns break pairing in the ledger.
   - Returning extra information without breaking `base, cand = seed_scores(...)` works with a 2-tuple subclass that carries `.dropped`.
2. **What failed, and why?**
   - Two red-team tests cannot pass under the card's rulings: the rerun test records the same row three times before it expects a
     refusal, and the string-tasks test expects acceptance where the card says refuse. This was only visible by reading the test bodies
     against the card, not the report's one-line summaries.
   - This session could not run `git mv` or `git rm` (approval needed, non-interactive). `0011` is a new file and `0008` is now a
     stub that says "delete me". The human should `git rm build/memory/decisions/0008-obs3-gain-rules.md`.
   - ruff's TRY004 wants `TypeError` for type checks, but the red-team test and the card want `ValueError`. Silenced in two places,
     with the reason given in decision 0011, rule 12.
3. **Which assumption was wrong?**
   - The red-team report's suggested fixes and its own tests do not always agree (fix 2 says "reject a second row", while the test
     accepts three). I assumed the tests encoded the report. Check the test body, not the summary.
   - Before this round I treated "a gain equal to 2 x noise is real". The card says "larger than", so equality is now noise.
4. **What should the next agent know?**

   - `seed_scores(...)` still unpacks to two lists, but check `.dropped`. Seeds that one arm missed, or that ran a different task
     set, are left out, so you may have fewer than 3 paired seeds and `is_real_gain` will refuse.
   - Seeds are plain `int`. Scores and costs are real numbers, not `bool`. Costs are finite and >= 0. All bad input raises `ValueError`.
   - The duplicate check is not a DB constraint (no migration this round). A future migration could add the UNIQUE index (known-bugs/obs3-limits.md).
