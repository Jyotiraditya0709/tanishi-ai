1. **What did we learn?** The card names no API, so the exam needs assumptions A1-A8 (class `Sandbox`, a result shape,
   default-deny confinement, worktree *copy*). Canaries must sit in places the sandbox cannot know in advance (temp dirs
   named like the vault, the store, `.env`), otherwise a path blocklist would pass. Against a deliberately naive stub
   (subprocess with a temp HOME, no confinement, throwaway, deleted) 21 of 56 tests failed: every read, write, network,
   CPU, memory, process-tree and Docker test. The 35 that passed are contract tests the stub legitimately meets.
2. **What failed, and why?** First draft asserted `os.stat`/`os.path.exists` on guarded files must fail; dropped as
   over-specifying (the card says "reading fails"; listing is still required, which is what RT-3 used). The rollback
   tests passed vacuously against a stub that ignored `worktree=`; added a positive control that the working copy holds
   the committed files.
3. **Which assumption was wrong?** Assumed the "worktree is reset" line meant `git reset` of the real worktree. A
   candidate working in the real worktree could read and change the real checkout while it runs, which contradicts
   line 2-3 of the card, so the exam assumes a copy (A6). If the implementer disagrees, they write `SB1-exam-conflicts.md`.
4. **What should the next agent know?**
   - The implementer must make the Frontier executor stage run through `Sandbox` (AR1 `run()` or the service); RT-2 and
     RT-3 are red until it does. `FrontierService` runs the executor in a *child process that imports `tanishi`*, so the
     profile must allow the interpreter, site-packages and the repo checkout read-only, while denying the sibling temp dirs.
   - The memory test needs enforcement that bites within ~4 s (RSS poll or `RLIMIT`; `RLIMIT_AS` is weak on macOS).
   - The setsid-escape case (`test_a_timeout_leaves_no_process_behind[setsid]`) is deliberately strict; the AR1 limit
     says a double-forked daemon escapes a process-group kill. If that cannot be met without Docker on macOS, write
     `open-problems/SB1.md` rather than weaken the test.
   - Tests leave `sleep 300` children only if the sandbox is broken; they are killed by a failing test or expire in 5 min.
   - Not covered: kernel/profile escapes, stdout flood, process-count limits, Docker network grant (host loopback).
