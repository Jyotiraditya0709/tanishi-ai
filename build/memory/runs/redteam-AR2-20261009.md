## Breaks (most severe first)

| id | sev | break | smallest fix |

| RT-AR2-1 | high | `run_python_tests` puts the nonce in `python -c <program>`. (`ps` shows it too.) | Pass the program on stdin or a file and never put the nonce in a place the candidate's interpreter can see; better, run the asserts in a harness process that execs the candidate source, and have the parent decide pass/fail from a result the candidate cannot print. ## Tried and held

- Cross-attempt bleed: every attempt has its own home and Core State db; a call in one task never counts in another.
- Tool call with no `tool_result`, a result with a different `call_id`, `success: false`, a tool name mismatch: all score 0.
- Broken hash chain: `real_calls` returns nothing.
- `log_expense` writes under the attempt's `TANISHI_HOME`, not the real `~/.tanishi`.
- No personal text, secrets or `*.db` in the task files; protected paths untouched.
- `os.sysconf("SC_PHYS_PAGES")` works on this macOS, so `system_check` can score here.

## Not tried

- Candidate code that floods stdout (the verifier buffers it all), writes outside its temp cwd, or double-forks out of
  the process group.
- Judge prompt injection (needs a real judge).
- Forged tool events via `emit()` is already written up in `tooltrace.py` and known-bugs; it stays open until W1.
