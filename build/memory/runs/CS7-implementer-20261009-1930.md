# CS7 · implementer run, 2026-10-09

1. **What did we learn?** "Byte for byte" for a WAL database means checkpoint first, then read the main file while
   holding `BEGIN IMMEDIATE` and confirm the `-wal` is empty. A `sqlite3` backup copy would not match the live file's
   bytes. Verifying everything in memory, staging beside the target and doing one rename made "leaves nothing on failure"
   cheap to get right.
2. **What failed, and why?** Nothing in the exam: all 39 tests passed on the first run with the tester's interface
   (S1-S4, C1-C2) as written. No conflicts file was needed. Ruff TRY004 flagged ValueError on type checks; I used a
   noqa for "malformed question file" (same as goals.py) and TypeError for the internal manifest check.
3. **Which assumption was wrong?** None I could find. The separate signing key (S3) and the 10/10 pass rule (C2) both
   fit. "Signed" is read as an HMAC, which is weaker than a real signature. That is written up in known-bugs.
4. **What should the next agent know?** The format is decision 0014. Change it only with a new `format` number. The
   nightly node must call `snapshot(dest)` once per destination and own pruning. The red team should attack
   `_open_bundle` with forged bundles (helper `forge()` in `tests/core_state/test_snapshot_impl.py`) and look for races
   on the restore target. Limits are in `known-bugs/cs7-snapshot-limits.md`. I did not read `vault/` or `builder_vault/`.
