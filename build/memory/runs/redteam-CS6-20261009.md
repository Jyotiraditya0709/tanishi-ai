Target: `tanishi/core_state/genome.py` at a7e1891. Proofs: `tests/core_state/test_genome_redteam.py`.
Breaks are `xfail(strict=True)`: the suite is green now; when a fix lands the test XPASSes, strict mode fails the run,

## Not a code break, but the next node will trip on it

- **Self-reported results.** `arena` and `attribution` are caller-supplied. Nothing proves they came from the Arena. A
  candidate (or a buggy hook) that can call `record_version` can write any score into the history. OBS3 must build the
  dict from the Arena's own output, not from anything the candidate touched. Before Mirror/M1 trusts these fields, they
  need a provenance field (Arena run id) it can check.
- **No secret/PII filter.** `attribution`/`arena`/`mirror_id` are free-form and stored as-is. A leaked token in a failure
  message would persist in an append-only table that cannot be scrubbed. Either document "ids and numbers only" or
  reject long free-text strings.
- **Merge-hook wiring (acceptance line 2) is not met**, as `open-problems/CS6.md` says. Not re-litigated here.

## Tried, and it held

- 6 processes racing one version: exactly 1 `ok`, 5 `IntegrityError`, one row.
- Lone surrogates and NUL in version or payload; NaN/inf; cyclic and 5000-deep nesting; mixed `int`/`str` keys: all
  refuse (or store exactly) and leave no partial row.
- SQL injection through version, genes, mirror_id: inert (bound parameters).
- Unknown parent leaves nothing behind; the child then succeeds after the parent is written.
- Caller mutating its dict after the call: no effect (serialised before the insert).
- Cost: 50 sequential writes, mean under 100 ms each (guard test). Each call reopens the db, rehashes migrations and
  re-checks them; fine at one write per merge, wasteful if anyone batch-imports history.
- Crash mid-write: the insert is one `with conn:` transaction in WAL, so a kill leaves either the whole row or none. I
  did not kill a process; this rests on SQLite's guarantee, not on a test.

## Verdict

Not safe to wire into the merge hook until G1, G2, G3 are fixed (each is a few lines, and each can corrupt or
duplicate the history). G4/G5 before Mirror reads the data. G7 needs the CS1 exam to allow schema version 2.
