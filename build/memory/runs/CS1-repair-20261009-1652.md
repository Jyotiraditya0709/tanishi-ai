# CS1 · repair run (red-team breaks R1-R16)

Result: 15 of 16 breaks fixed (R8 stays xfail by the human's ruling). Full suite: 148 passed, 1 xfailed, 10 failed. The 10
failures are exam cases that contradict the red team, accepted by the human (`open-problems/CS1-exam-conflicts.md`).

1. **What did we learn?**
   - SQLite stores a bound NaN as NULL, so `CHECK (x BETWEEN 0 AND 1)` alone lets NaN in. You also need NOT NULL.
   - `BETWEEN 0 AND 1` on a REAL column already rejects text like `'high'`, because text sorts above every number.
     No `typeof()` check is needed.
   - SQLite gives `-wal` and `-shm` the db file's mode, so creating the db 0600 before the first connect is enough.
     `open_db` still re-tightens all three on every open.
   - `migrate()` has to own its bookkeeping tables (`CREATE TABLE IF NOT EXISTS schema_version / schema_checksum`), because test
     migrations do not always create `schema_version`.
2. **What failed, and why?**
   - Three red-team tests cannot pass alongside the exam (R14, R10 and R8; see the conflicts file). This was only visible by reading
     both test files side by side. The red team checked its own tests against the code, not against the exam.
   - A BSD `sed` multi-line edit to remove the xfail marks silently did nothing. I used a short Python script instead.
3. **Which assumption was wrong?**
   - "Fix all 16 and keep the suite green" assumed the red-team tests and the exam agree. They do not in three places.
   - Decision 4's `schema_version.checksum` column and decision 8's autouse `TANISHI_HOME` both assumed the exam allowed them.
     It does not, so I used a sibling `schema_checksum` table and a temporary `HOME` (decision 0007).
   - The red team's "never edit 0001" was superseded by the human's "nothing has shipped". From now on 0001 really is frozen,
     and `migrate()` enforces that with its checksum.
4. **What should the next agent know?**
   - New schema change = new `migrations/000N_lowercase_name.sql`. No `BEGIN`/`COMMIT` in it. Never edit an applied file.
     If you must change 0001 before release, every dev db has to be deleted (its checksum will not match).
   - `events`: insert only. Read the tail and insert in one `BEGIN IMMEDIATE`. `prev_hash` is UNIQUE, so retry on conflict.
     Tamper tests must `DROP TRIGGER events_no_update` / `events_no_delete` first.
   - Every confidence must be a float in [0, 1]. JSON columns take `json.dumps(...)` or NULL. Evidence and goal parents must exist
     (FKs are enforced, and deleting a belief that has evidence is refused).
   - The tester agent needs to amend `test_migrations.py` (10 failing cases). CS2 should read `open-problems/CS1-design-notes.md`
     before building the event writer.
