# Red-team · CS3 belief store and legacy importer · 2026-10-09

Branch `agent/memory/cs3`. Tests: `tests/core_state/test_beliefs_redteam.py` (18 tests: 9 breaks as `xfail(strict=True)`, 9 attacks that held).
Nothing in `tanishi/` or `scripts/` was changed. Fixes are the implementer's; each strict xfail turns red when its break is fixed, and the mark must then be removed.

## Breaks (most severe first)

| # | Sev | Break | Smallest fix |
|---|-----|-------|--------------|
| R9 | medium | Importer: legacy `city` Lisbon -> Porto -> Lisbon leaves Lisbon and Porto both live and contested while legacy says only Lisbon. The importer never retires, and the reverted value's id already exists, so it is skipped. Every legacy edit needs a manual `retire()` and the stale value stays queryable. | When a legacy-sourced `(user, key)` changes, retire the previous legacy belief for that key instead of contesting it. |
| R8 | medium | Importer: one legacy TEXT value that is not valid UTF-8 aborts the whole import (exit 1, zero rows written). The error message also echoes the undecodable text to stderr (personal data). | Set `conn.text_factory` to decode with `errors="replace"`, or skip and count bad rows; never print row content. |
| R4 | medium | `("User","name","Al")` and `("user ","Name","Bob")` do not contradict: both stay active. LLM-written beliefs vary in spelling, so the contradiction check is easy to evade. Already listed as "matching is exact" in known-bugs; severity raised because it defeats acceptance bullet 1 in practice. | Compare subject and predicate on a normalised key (strip, casefold); keep the original text for display. |
| R1 | medium | `retire(id, reason)` copies the free-text reason verbatim into `events.payload`. CLAUDE.md: no secrets or personal data in events. Decision 0008 keeps belief text out of events but not the reason. Events become append-only once CS2 lands, so a pasted secret is permanent. | Store a short reason code, or a hash plus length; keep the text out of the log. |
| R7 | low (design) | No function reads evidence back. `evidence` rows are written and never listed, so "every belief has evidence" cannot be checked or used by the next node (M1 retrieval). | Add `evidence_for(belief_id) -> list[Evidence]`. |
| R5 | low | The same triple added twice makes two active rows with separate confidence and no link. `find()` returns duplicates. | On an exact live duplicate, return the existing belief and attach the new evidence to it. |
| R6 | low | `contradictions()` trusts the caller's fields: a forged `Belief` with an unknown id reports conflicts. | Look up the stored row by id and use its fields; raise `LookupError` for an unknown id. |
| R2 | low | `evidence_event_id=True` is accepted and links evidence to event 1 (bool is an int). | Reject bool and non-int, as `_clamp` does for confidence. |
| R3 | low | `confidence=10**400` raises `OverflowError`, not a clamp. Spec says clamp. | Catch `OverflowError`; clamp to 1.0 or -1.0 sign-wise. |

## Attacks that held

- Random add/retire sequences (150 steps, seeded): a live belief is contested iff a live peer disagrees. No stuck or phantom contested status.
- 16 threads adding conflicting beliefs: all end up contested, 15 conflict events, no lost check.
- Bad `evidence_event_id` (foreign key failure): whole add rolls back, including the peer's flip to contested; no event row.
- Lone surrogate text: raises, writes nothing.
- Conflict events carry ids only, no belief text.
- 4 importer processes at once on the same file: exactly 40 rows, no duplicates, all exit 0.
- Importer with `inf`, negative, NULL importance and NULL category: clamped or defaulted, no CHECK failure.
- Importer leaves the legacy file byte-identical; garbage file exits non-zero with no traceback and no writes.
- Cost: about 1 ms per `add_belief` despite open+migrate per call. No performance break; the known-bugs note about per-row opens in the importer stands but is not urgent.

## Not tried

- Hash chain: CS3 writes unhashed events, so there is nothing to corrupt yet (known, decision 0008 point 5). Re-attack when CS2's `emit()` replaces `_emit`; unhashed rows already in the table may confuse the chain's first link.
- Evaluation leakage and the Sealed Vault: CS3 touches neither.
- Crash mid-write by `kill -9`: SQLite WAL plus one transaction per add; not simulated beyond the rollback tests above.
