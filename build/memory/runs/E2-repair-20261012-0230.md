## Four answers

1. **What did I learn?** The red team's proposed fixes and the exam make different assumptions about what a
   proposal is. The exam treats a proposal as a bare `(organ, gain, real)` row: repeats are fine, and negative real
   gains count. Any "identity" or "harm" rule has to be added beside those rows, not on top of them. A verdict carries
   enough (`effect`, `threshold`) to test the reverse direction without running anything again, because OBS3's noise
   is the larger arm's and so the same in both directions.
2. **What failed and why?** Four red-team tests cannot pass. The two RT-1 tests call with 3 seeds, which the card
   now refuses. The two RT-7 tests need either a refusal or a harm penalty that the exam's proposal-order test rules
   out (that test has unreal gains down to -0.05 and real negative gains). They keep their markers; the reasons are
   written up in the conflicts file.
3. **What assumption was wrong?** That "remove the marker when fixed" and "the card's fix" always line up. For RT-1
   the break is closed, yet its proof still fails, because the proof uses the very input the fix now refuses. Also,
   the card's RT-2 wording ("a true +0.01 is real") contradicts rule 7 and the exam; I kept "not real" (conflict 4).
4. **What should the next agent know?** Build organ proposals with `Attribution.proposals(organ_of)`, not by hand:
   it adds gene ids and counts real harm. Treat `Attribution.complete is False` as "the gain is real, the credit is
   unknown". R2 must fix the seed list before it sees a score and record how many lists it tried. `causal.MIN_SEEDS`
   (5) is not `attribution.MIN_SEEDS` (3).
