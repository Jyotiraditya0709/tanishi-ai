# CS2 · tester · 2026-10-09

1. **What did we learn?** The CS1 triggers block honest UPDATE/DELETE on `events`, so tamper tests must `DROP TRIGGER` first
   (an attacker with file access can). The tests also check that honest writers are refused. `emit()` takes no connection,
   so tests read the log through the shared Core State db (`TANISHI_CORE_STATE_DB`).
2. **What failed, and why?** Nothing ran against an implementation (I did not read it). The suite fails at import today
   (`tanishi.core_state.events` missing), so it fails on an empty implementation.
3. **Which assumption was wrong?** None known yet. Assumptions the builder may hit: `Event` has attributes
   `id, ts, kind, actor, session_id, payload (dict), prev_hash, hash`; `since` compares `ts >= since` as strings;
   tests mock `TanishiBrain` via `object.__new__` and patch `_select_model`/`_think_ollama`.
4. **What should the next agent know?**
   - The spec does not pin the canonical-JSON layout, so the recompute test accepts sorted keys with compact or default
     separators, and payload as parsed object or stored text.
   - Not tested, because the spec is silent: deleting the *last* row (a chain alone cannot see it; AUTOINCREMENT or a
     sqlite_sequence check could), and whitespace-only edits to stored payload text (detected only if the hash covers
     the stored text rather than re-serialised JSON). Worth a decision if the red team cares.
   - Deleted-row tests accept the deleted id or the next id as "first bad id".
   - Property tests use seeded `random`, not hypothesis (not a declared dependency).
