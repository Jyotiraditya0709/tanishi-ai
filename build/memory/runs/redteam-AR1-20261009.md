## Found, no test (lower severity, or hard to prove deterministically)

- **Env is inherited.** Isolation is by variable, not a sandbox: `pwd.getpwuid(os.getuid()).pw_dir` still reaches the real home,
  and API keys are visible to `setup`, executor and verifier. Needed for the executor today, but the verifier and `setup` should
  get a scrubbed env. Say so in decision 0008.
- **Daemonised grandchildren escape.** `_kill` uses the attempt's process group; a `setup` that double-forks and calls `setsid` survives.
- **Cost is lost on failure.** A timed-out or crashed executor records cost 0 (and NaN/negative cost silently becomes 0), so spend
  is undercounted. Rule 4 says usage is the budget; record `cost=None`/flag instead of 0.
- **Infra failures look like candidate failures.** Spawn failure, setup non-zero and import errors all score 0, same as a wrong
  answer, and are told apart only by free text in `meta.reason`. Add `meta.kind` (`candidate|verifier|infra`).
- **Duplicate YAML keys.** `safe_load` keeps the last one silently. Use a loader that rejects duplicates.
- **Performance.** One spawned interpreter per (task, seed), run serially: ~0.15 s overhead each, so 100 tasks x 3 seeds is ~45 s
  of pure overhead before any model time. Fine now; a worker pool will be needed at AR2+.
- **Spawn re-imports `__main__`.** A caller script without an `if __name__ == "__main__"` guard re-runs itself in every attempt.
- **Tracked, not mine:** `.gitignore` `runner.*` (known-bugs/gitignore-runner-pattern.md); exam test C1 still fails.

## What I tried and found sound

Verifier raising, NaN, inf, bool, wrong shape, out-of-range: all score 0. Hard exit, blank/whitespace output, wrong executor
return type: 0 and the verifier is not called. Timeouts kill the group. `Task` rejects bool/NaN/inf/negative timeouts, non-string
fields, unknown and missing keys; YAML is `safe_load`. The caller's `os.environ` is not modified. Rows: one per (task, seed), seeds
distinct, JSON `meta` valid. No db file or secret was committed by this work.
