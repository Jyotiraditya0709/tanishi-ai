Code: `tanishi/core_state/genome.py`. Exam: `tests/core_state/test_genome.py` (the tester's, unchanged). Full suite: 202 passed.

1. **What did we learn?** The CS1 schema already gave CS6 most of what it needed: `version` PRIMARY KEY makes a second
   write fail, the `parent` FK rejects unknown parents, and `json_valid` on a TEXT column keeps `1.0` a float. The code
   validates the arguments, `json.dumps(allow_nan=False)` before it opens the db (so bad input never writes and later edits by the caller
   cannot leak in), then runs `migrate()` and one INSERT in one transaction.
2. **What failed, and why?** Nothing in the tests. A DB-level append-only guard (UPDATE/DELETE triggers) could not ship:
   it needs migration `0002`, and the CS1 exam hard-codes schema version `1`. See `known-bugs/cs6-genome-not-append-only-in-sql.md`.
3. **Which assumption was wrong?** That "append-only" could be enforced in the schema from this node. With the
   current exam, it holds only on the `record_version()` path. The tester's layout assumption (keys = parameter names)
   was accepted. `version` and `parent` are also in the record (decision 0008).
4. **What should the next agent know?** Acceptance line 2 (one record per merge) belongs to OBS3/CI and is not wired
   here; `open-problems/CS6.md` lists what that hook must handle (an idempotent retry, recording the parent first, where the db persists).
   This node produces no intelligence, so it has no benchmark.
