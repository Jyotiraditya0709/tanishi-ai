# W1 · Warden wiring · ToolRegistry.execute() asks the guard first · 2026-10-10

`execute()` now calls `tanishi.guard.check` before anything else when `registry._GUARD_ON` is true. That switch reads `TANISHI_GUARD` (1/true/on/yes) once at import and is off by default; production launchers set `TANISHI_GUARD=1`. On deny it returns early with "Warden denied <tool>: <reason>". On ask the call needs approval, through the same fail-closed approval path that `requires_approval` uses. On allow nothing changes. New tests are in `tests/guard/test_registry_gate.py`.

1. **What did we learn?** `execute()` already had a local `session_id` from `current_task()`, which feeds the CS2 events. The new `session_id` parameter goes to the Warden only. If it is not given, the guard gets the current task's session. Events still use the task's session, so CS2 behaviour is unchanged. `_refuse()` now takes `need_approval` (`guard_ask or tool.requires_approval`). The CS5 "not predicted" check uses the same flag, so an `ask` with no approver is not predicted, matching the docstring contract.
2. **What failed, and why?** Nothing in the suite. A first draft of the "off by default" test reloaded `tanishi.tools.registry` inside the suite. That would make new `ToolResult`/`ToolRegistry` classes and could break `isinstance` checks in later tests, so it was replaced with a check in a fresh subprocess.
3. **Which assumption was wrong?** That the parameter name `session_id` was free inside `execute()`. It was not (see 1).
4. **What should the next agent know?** A Warden deny returns before the tool_call event, so denied calls are **not** in the Core State event log. The Warden's own log must hold that audit trail, or a later node should emit a `tool_denied` event. `guard_check` is a blocking socket call (default timeout 5 s) made directly inside the async `execute()`, so a slow Warden stalls the event loop. A later change could use `await asyncio.to_thread(guard_check, ...)`. The ruff findings in `registry.py` (10) are older than this change and were left alone. The new test file is clean.
