# SB1 · implementer run (2026-10-11)

Built `tanishi/sandbox/` (core.py, backends.py, _launch.py) and wired AR1's executor stage through it. Exam: 56/56 on
macOS (Docker test included) and on Linux (python:3.12-slim container, Landlock, Docker test skipped). AR3 RT-2/RT-3
pass. Full suite: 1 failed (AR1 `test_partial_run_leaves_no_rows`, a real conflict, see
`open-problems/SB1-exam-conflicts.md`), 2231 passed on both platforms.

1. **What did we learn?** macOS hides the environment of platform binaries (`/bin/sleep`) from `ps -E`, so an env
   marker cannot find a setsid child. `sandbox_check(pid, "file-read-data", PATH, p)` can: it answers per profile,
   but only for paths that *exist* (a `literal` on a missing path always reads as denied). Landlock + seccomp gives an
   unprivileged default-deny sandbox on Linux; making the launcher a child subreaper keeps setsid orphans in the tree.
2. **What failed, and why?** First kill order (killpg, then look for children) lost setsid children: once the root
   died they were reparented to launchd and no longer descendants. Snapshot first, then kill. The env marker
   (`TANISHI_SANDBOX_RUN`) broke AR1's minimal-env exam, so it was replaced by the two mechanisms above.
3. **Which assumption was wrong?** That every existing test could stay green once RT-2 holds: AR1's partial-run test
   signals through a file outside the executor's home. Also that Linux could just be "bwrap": CI's ubuntu has no
   bwrap and restricts user namespaces, so Landlock was the only unprivileged option.
4. **What should the next agent know?**
   - Start candidate code with `Sandbox.run`/`popen`; read `decisions/0025-sandbox.md` first. A task that needs the
     network must carry the tag `network`.
   - Only `python -m pytest` runs without approval in this setup; probe Linux by running the suite in a
     `python:3.12-slim` container (install git + `pip install -e .`, run as a non-root user).
   - CI needs a kernel with Landlock ABI 4 (Ubuntu 24.04's 6.8 has it). If CI lacks it, `pick_backend` raises and
     the sandbox tests fail loudly rather than run unconfined.
   - Limits not covered: `known-bugs/sb1-sandbox-limits.md`. The red-team round has not run yet.
