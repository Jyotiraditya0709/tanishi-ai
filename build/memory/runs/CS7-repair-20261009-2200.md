# CS7 · repair round · 2026-10-09

Code: `tanishi/core_state/snapshot.py`, `tanishi/core_state/continuity.py`. All eight CS7 red-team tests (R1 to R8) now pass and
their xfail marks are removed. No exam or red-team assertion changed. No migration was added. Decision 0014 is now
`decisions/0015-snapshot-bundle-format.md` (git mv), updated with the repair rules. The bundle `format` is still 1.

1. **What did we learn?** Validate at write time with the rule the reader applies. R1 existed because snapshot() and
   restore() had two different ideas of a legal path. Now `_check_capture_path` calls restore's own `_check_path`, so the
   two cannot drift. That fixed R1 by widening the reader (on POSIX, `\` is an ordinary character) rather than refusing
   the name. The red-team R1 test needs the file to round-trip, so refusing it would have failed that test. For R2, the
   staged db is `quick_check`ed with `mode=ro&immutable=1`, which leaves no `-wal`/`-shm` in the restored home. A pinned test
   checks that the restored home holds only its own files.
2. **What failed, and why?** Nothing broke the exam. One design choice turned out to be unsafe. On Windows, the
   obvious pid liveness probe, `os.kill(pid, 0)`, terminates the process. So the sweep checks pid liveness on POSIX only
   and goes by age (24 h) elsewhere. Also, once matching is whole-answer, the R4 "contains another expected answer" rule
   can never fire on its own. It is kept as a second guard in case matching is loosened for prose answers. It skips text
   that is part of the question's own expected answer, so "New Delhi" next to "Delhi", or two questions both expecting
   "yes", can still pass.
3. **Which assumption was wrong?** That the R4 fix and the R7 fix were separate pieces of work. Whole-answer matching
   (R7) already settles R4 and R6. The second assumption was that duplicate *expected* answers could be refused at load
   time. The R7 red-team test uses ten questions that all expect "no" and needs `run()` to return a result, so only
   duplicate *questions* are refused. Nothing went into `open-problems/CS7-repair-conflicts.md` because no fix
   conflicted with a test.
4. **What should the next agent know?** Answers must now be the bare fact. The brain-side answerer has to reply with the
   bare answer, not "It was X" (see `known-bugs/cs7-snapshot-limits.md`). The nightly node must: call snapshot()
   once per destination; choose bundles by manifest `created_at` (rollback is still accepted by design); run the
   Continuity Test from a process the candidate cannot call (it is an oracle); and delete by hand any staging left
   by code from before this round, because those names carry no pid. HMAC signing, the key-loss risk and the lost
   executable bit remain as documented limits.
