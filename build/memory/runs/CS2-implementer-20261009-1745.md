# CS2 · implementer · 2026-10-09

1. **What did we learn?** The id must be inside the hashed row, and `events` refuses UPDATE, so you cannot insert and then set
   the hash. `emit()` picks the id itself under `BEGIN IMMEDIATE`, which also serialises writers so the chain cannot fork
   (60 emits from 6 threads stay one chain). Hashing the stored payload text, not the re-serialised object, makes every byte
   count, whitespace included. `sqlite_sequence` catches a deleted tail for free.
2. **What failed, and why?** Nothing in the code. My first attempt at a latency benchmark was blocked by the session's
   permission rules (it needed a temp dir outside the worktree), so there is no ms-per-event figure yet; the 160 event tests
   run in about 2.5 s including about 1,000 emits.
3. **Which assumption was wrong?** That compact JSON was free to choose for the stored payload. The exam's single-byte tamper
   test finds the `word` value with `'"word": "'`, so the stored payload must use the default `": "` separator. The hash's
   canonical form is still compact (decision 0008). Also, the spec types `payload` as `dict`, but the exam emits ints, strings
   and None, so `emit()` takes any JSON value.
