The red-team tests had no xfail marks to remove: they failed outright and now pass.

1. **What did we learn?** The only trustworthy pass/fail is one the verifier computes itself from values the candidate
   had to produce. A nonce was the wrong tool for code tasks: anything the candidate's interpreter can see, it can
   print. Now candidate code runs in `_code_harness.py` (its own process, PATH/LANG/temp HOME only), answers calls,
   and the asserts run in the verifier, comparing type and value with a reference on random cases. For tool tasks the
   same idea: a value counts only if it came out of a tool (in the output, not in the input) and was random for this
   attempt, read back from `$HOME/.arena/truth`.
2. **What failed, and why?** Nothing at runtime. Two existing tests had to change their *setup* (allowed by the card):
   `test_setup_plants_the_value_the_verifier_looks_for` looked for literals the red team requires to be gone, so it now
   runs each setup six times and checks fixture, truth record and that the value varies (stronger); the tool-verifier
   fixtures now plant the truth file, and the `count_matching_files` fixture lists all 7 logs instead of 3 (an answer
   of 7 from a listing of 3 is exactly the "tool did not produce the answer" case).
3. **Which assumption was wrong?** That a verifier's 0 is always "scored". A runaway query or hung code is the
   candidate's fault and the card wants it logged so: added `CandidateFault` (a `Verdict` subclass, so existing callers
   see a plain 0) and one branch in the runner. Also: `memory_recall` cannot be a one-turn prompt and test memory;
   setup now plants a random color in the attempt's `$TANISHI_HOME/memory/user.md` (no legacy db touched). Today's
   brain does not read that folder, so it will score 0 there until memory is wired in. That is the honest number.
4. **What should the next agent know?** Planted values live in `.arena/truth` (`key=value`, keys may repeat); write new
   tool tasks the same way and use `produced()` / `produced_int()` in `checks.py`. Any tool input naming `.arena` scores
   0. Code tasks: pass a `tests(ns)` function to `run_python_tests` and compare with `same()`. Setup randomness reads
   `</dev/urandom` (see the residuals in `known-bugs/ar2-redteam-20261009.md`). OBS3/CEI can now filter rows on
   `json_extract(meta, '$.tags')`; nothing does that yet.
