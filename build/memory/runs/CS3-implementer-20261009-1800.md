Built `tanishi/core_state/beliefs.py` and `scripts/import_legacy_memory.py`. The tester's exam (`tests/core_state/test_beliefs.py`)
passes in full with no change to it. My own tests are in `tests/core_state/test_beliefs_impl.py`. Full suite: 256 passed.
No benchmark: the node stores beliefs and does not produce intelligence.

## 1. What did we learn?
- One `BEGIN IMMEDIATE` around "find live peers, insert, mark contested, write event" is enough to make two concurrent writers
  see each other. No locking beyond SQLite's is needed.
- Opening, migrating and closing per call is cheap enough (the whole exam runs in about 2 s), so the no-connection interface works.

## 2. What failed, and why?
- My first `retire()` stored the reason as an evidence row. The exam asserts retire leaves the evidence count unchanged, so the
  reason moved to a `belief_retired` event. Evidence now only means "what supports this belief".

## 3. Which assumption was wrong?
- That free-text legacy memories map onto subject/predicate/object. They don't. Under the spec's contradiction rule, every
  `("user", "fact", ...)` memory would contest every other one. Each memory gets its own subject `memory:<id>` instead (decision 0008).

## 4. What should the next agent know?
- Decision 0008 has the status, event and legacy-mapping rules. Known limits are in `known-bugs/cs3-belief-store.md`.
- CS2: swap `beliefs._emit` for `emit()` so belief events join the hash chain. Payloads carry ids only; keep it that way.
- `add_belief_if_absent(id, ...)` is the idempotent entry point for any importer. It takes a caller-chosen deterministic id.
- The importer opens the source with `mode=ro`, refuses the Core State db itself as a source, and adds `sys.path` so it runs
  as `python scripts/import_legacy_memory.py <path>` without an install.
