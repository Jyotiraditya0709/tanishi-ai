# OBS1 · repair round, 2026-10-10 22:38

Fixed all twelve red-team breaks (R1-R12) in `tanishi/observability/trace.py`. All 14 OBS1 xfail marks are removed
and those proofs pass. Decision renamed to `decisions/0023-traces.md` and extended. New:
`open-problems/OBS1-trace-leakage.md` (for SEC1) and `open-problems/OBS1-repair-conflicts.md`.

1. **What did we learn?** A generator runs in its consumer's context, so a ContextVar alone cannot tell "the code
   inside the span" from "the code that pulled one item and moved on". The fix asks the stack: a span remembers
   the generator frame it was opened in, and while that frame is not running, events and child spans skip it.
   `@contextmanager` wrappers are generators too, so frames driven by contextlib are treated as wrappers. Without
   that, any `traced()` helper would have lost its body's events.
2. **What failed, and why?** The R5 proof kept failing after the fix. It calls `monkeypatch.undo()`, which also undid
   the conftest's `HOME` isolation, so `load()` read the real `~/.tanishi`. Two core_state test files call `undo()`
   too, and their remaining lines were running against the real home and db. The conftest now uses its own
   MonkeyPatch (see repair-conflicts). Also, the edit tool turned the escape `" "` into the raw character in
   source; `chr(0x2028)` is now used instead.
3. **Which assumption was wrong?** That a failed record should be dropped whole. One bad value (an int past 4300
   digits) cost the span and its event links. Now values are checked one at a time and a bare record is the
   fallback. Also wrong: a CLI that prints JSON-sourced text is safe. Model-chosen tool names reach the terminal,
   so every printed field is escaped now.
4. **What should the next agent know?** Wiring `think()` and `ToolRegistry.execute()` is the next node's job
   (decision 0023 point 11). Pass ids and lengths only, never prompt or reply text (point 10). For streaming, open
   the span in the consumer, around the whole loop (point 7). A tool passed in `tool_calls=` and also emitted by the
   registry counts once, so the registry span can pass its tool name safely.
