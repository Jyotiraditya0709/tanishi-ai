## Not a code break, but the next node will trip on it

- **Rollback is accepted.** An older, validly signed bundle restores without complaint (pinned by
  `test_old_bundle_restores_old_state_by_design`). A stale copy placed in the "latest" slot silently turns back her
  beliefs. The nightly node should pick bundles by the manifest `created_at`, not by file mtime, and restore() could
  return that stamp so the caller can show it.
- **Hidden questions are handed to the answerer in plain text**, and `ContinuityResult.correct` is a per-run oracle: a
  candidate that may call `run()` repeatedly can learn each expected answer by trial. Only run the real vault file
  from a process the candidate cannot call, and never return `correct` to it. `missed` also carries question text
  (personal history); do not log it.
- **Stale debris after SIGKILL.** `.snapshot-*.part` in the destination and `.<home>.restore-*` beside the target
  (the latter holds a plaintext db copy) are removed on exceptions but not on a hard kill. The nightly node should sweep both.
- Weak signing keys (e.g. `"a"`) and using the same string for both keys are accepted. Low; add a minimum length when
  the nightly node generates the keys.

## Tried, and it held

- Concurrent writer thread during 8 back-to-back snapshots: every bundle restores, `integrity_check` is `ok`, no writer errors.
- Interrupt (`KeyboardInterrupt`) at the rename in snapshot() and in restore(): no `.part` file, no staging dir left.
- Symlink as a skill file: refused. Traversal and absolute paths in a manifest, byte flips, truncation, wrong keys: covered by the exam and held.
- Keys and file content never appear in error messages (read the code paths; every `raise` uses a fixed string).
- Snapshot does not change the live db and never touches the legacy db paths.
