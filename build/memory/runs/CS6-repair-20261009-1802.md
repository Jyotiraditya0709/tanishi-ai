1. **What did we learn?** Validation before `json.dumps` is not enough when `json` itself is lossy: it quietly turns
   tuples into lists and `1` keys into `"1"`. The record now checks for exact plain JSON types (`type(x) is ...`) before it
   serialises, and turns `genes_changed` into a list once so a generator is never drained by the checks. Every
   refusal still happens before the db is opened, so a refused call writes nothing.
2. **What failed, and why?** Refusing duplicate gene names (G6) broke 4 cases of the exam's random-history test, whose
   generator repeats names (`g{randrange(50)}`) and expects them back. The test wins: duplicates are kept, and only the
   `["a","a"]` case of the red-team G6 test keeps its strict xfail. See `open-problems/CS6-repair-conflicts.md`.
3. **Which assumption was wrong?** That every fix on the card was compatible with the exam. Running the exam before
   writing the fix would have shown it: run each new refusal against the exam's generators first.
