# Red team · E2 · 2026-10-12

Proofs: `tests/observability/test_redteam_e2.py`. Breaks are `xfail(strict=True)`; the fixer removes the marker when fixed.
Scope: `tanishi/observability/causal.py` (`verify_gain`, `attribute`, `organ_scores`, `Attribution`) on OBS3 rules.
Result: 17 xfail (breaks, 7 distinct findings), 9 pass (attacks that held). `ruff` clean. Nothing in `tanishi/` was changed.

## Breaks (most severe first)

1. **MED · E2-RT-6 · a real gain can land on no gene, and nothing says so.** Leave-one-out sees no drop when two genes are
   redundant (either alone gives +0.3). `attribute(["r1","r2"], ...)` gives `total.real` True, both genes `real` False, so
   both organs score 0 and `as_dict()` records a real total with zero credited genes. The documented limit only covers
   over-credit from interacting genes (`e2-causal-limits.md`), not this under-credit. Test:
   `test_redundant_genes_do_not_leave_a_real_gain_unattributed`. Fix: add `Attribution.unattributed =
   total.effect - sum(effect of real genes)` (and put it in `as_dict`) so a consumer can see credit is missing.
2. **MED · E2-RT-1 · the 3-seed minimum accepts a no-effect change 2.0% of the time.** Measured (6000 trials, equal
   means, sigma 0.1): 3 seeds 2.0%, 4 seeds 0.7%, 5 seeds 0.37%, 6 seeds 0.07%. E2's evaluation only measured 6 seeds
   (0.5% in its own setup), so the weakest allowed setting was never reported. The caller also owns `seeds`, so a loop
   over 3-seed subsets finds one that passes: 1 of 100 subsets accepted a change that does nothing
   (`test_null_change_false_accept_rate_at_minimum_seeds`, `test_a_null_change_can_be_pushed_through_by_choosing_seeds`).
   Honest note: 2% is inside the 5% OBS3's red team accepted; this is a trap for the next node, not a gate failure.
   Fix: `_check_seeds` in `causal.py` requires at least 5 seeds (leaves OBS3 `MIN_SEEDS` alone), and the caller records
   how many seed sets it tried (R2).
3. **MED · E2-RT-3 · bad input escapes `ValueError` (decision 0011 rule 12).**
   - Unhashable versions (`{"v": 1}`) raise `TypeError` (arms are dict keys).
   - Arms equal under `==` but different under `str()` (`1`, `1.0`, `True`) pass the "must differ" check, merge into
     one dict key, and the verdict is "no gain" with `run_fn` called twice for the same arm. Silent wrong answer.
   - An int too big for a float (`10**400`) as a score, `min_effect` or `gain` raises `OverflowError`.
   - Finite but huge scores (`1e308` vs `-1e308`) overflow `fmean`/`fsum` with `OverflowError`; the same for two `1e308`
     gains in `organ_scores`.
   - `seeds=5` or `changes=None` raise `TypeError` from `list()`.
   Fix: key `_run_interleaved` by arm index, not value; compare arms with `==` as well as `str()`; wrap the numeric
   checks in `try/except (OverflowError, TypeError)` and re-raise `ValueError`; require `|score| <= 1e6`.
4. **LOW · E2-RT-5 · `Attribution` cannot be copied, pickled or `dataclasses.asdict`-ed.** `genes` is a `MappingProxyType`.
   R2 or an Arena worker that returns it across a process boundary, or deep-copies a result, will crash.
   Fix: store a plain `dict` (frozen dataclass already stops reassignment) or add `__reduce__`.
5. **LOW · E2-RT-7 · organ scores do not punish harm and trust identity.** A proposal whose gene effect is negative has
   `real` False, so it adds 0: an organ that proposes only harmful changes scores the same as a quiet one. `real=True`
   with a negative gain is accepted, and the same proposal passed twice is counted twice (no gene id on a proposal).
   Documented partly as "trusts its input". Fix: add a `gene` key and refuse duplicates; decide whether harm counts
   (a `penalty` of the negative effect when the verdict is significant in the wrong direction).
6. **LOW · E2-RT-2 · the 0.01 floor is not exact.** Rule 7 says a gain equal to the floor is not real. A true +0.01 is
   called real for about 60% of score levels because of float error (`0.31 - 0.30 > 0.01` is True, `0.71 - 0.70` is
   not). Test: `test_floor_boundary_does_not_depend_on_the_score_level`. Fix: compare with a tolerance
   (`effect <= threshold + 1e-12`) or round `effect` to 12 places in `is_real_gain` (OBS3 file, so a human decision).
7. **LOW · E2-RT-4 · `verify_gain`'s `Verdict` is not JSON-safe with `min_effect=Fraction(...)`** (the threshold stays a
   `Fraction`). `attribute().as_dict()` casts to float, `verify_gain` does not. Fix: cast `effect/noise/threshold` to
   float in `Verdict` construction.

## Tried, held
- One lucky or one crashed seed (single 0.9 outlier in 10 seeds): rejected, the outlier lifts the noise bar faster than the mean.
- Seed order, arm order and idempotence: verdicts equal under reordering; global `random` state untouched.
- Passenger riding with a winner, harmful gene, single-change attribution (equals total), `run_fn` exception mid-run
  (propagates, no partial result, nothing written).
- Unreal proposals cannot inflate an organ (50 x gain 99.0 unreal = 0.0).
- 150 changes x 6 seeds finishes in well under 15 s.
- Not reachable: hash chain and DB corruption (`causal` writes nothing; `as_dict` goes to `genome.record_version`, whose
  own checks held for NaN), Frontier/Vault leakage (nothing here touches them), secrets (`reason` holds numbers only;
  gene names are caller text, a note for R2).
- Seed-ignoring scorer: noise is 0, a 0.011 gain is "real". That is OBS3 rule 7 working as decided, kept as a test so
  nobody reads it as repeated evidence.

## Not fixed here
Red-team role: tests and notes only. The E2 implementer owns the fixes; items 1, 2 and 3 first.

## After-task answers
1. **Learned:** the n+2 ablation design is sound for additive genes, and its failure modes are at the edges: redundancy
   (no credit) and few seeds (2% false accept). Both are invisible in the output unless you look for them.
2. **Failed and why:** nothing in the node broke the OBS3 gain rule; the breaks are around it (input types, float
   boundary, credit accounting).
3. **Wrong assumption:** "evaluated at 6 seeds, so the rule is 0.5% safe". The rule allows 3 seeds, so the guarantee
   is the 3-seed number.
4. **Next agent:** R2 must pick the seed set before it sees any score and record how many sets it tried. Treat
   `Attribution.total.real` with zero real genes as "gain exists, credit unknown", not as "no gain".
