# CS4 · implementer run

1. **What did we learn?** SQLite does not allow `WITH` (and so no recursive CTE) inside a trigger. To reject a cycle in
   the database, I used a closure table (`goal_ancestors`) that triggers keep up to date on insert, re-parent and delete.
   A re-parent is then one indexed lookup. All 59 exam cases pass, and so do 25 implementer cases, including a
   random-move property that checks the closure table against the real tree.
2. **What failed, and why?** The first version was `migrations/0002_goal_tree.sql`. It broke 37 CS1 exam cases: 34 pin the
   schema version at 1, and 3 write random owners, which an owner CHECK trigger rejected. Both were reverted. Under
   the "test wins" rule, `goals.py` installs the objects itself. See `open-problems/CS4.md`.
3. **Which assumption was wrong?** That decision 0007 ("every schema change is a new migration") could be followed. The
   CS1 exam makes any 0002 fail. The tester's note had the same assumption.
4. **What should the next agent know?**
   - The CS1 exam must be loosened before anyone adds a migration. That blocks every later Core State node, not only CS4.
   - Rank direction: higher first (decision 0008).
   - `goals.py` imports the private `db._statements` to split its trigger script. Keep the two in step.
   - No benchmark: this node produces no intelligence.
