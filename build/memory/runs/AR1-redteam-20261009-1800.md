# AR1 · red-team run (2026-10-09)

1. **What did we learn?** Failures are handled well (every verifier or executor failure scores 0). The weak spot is the opposite
   direction: the runner does not protect the verifier from the candidate. Same process, same `/tmp`, answers echoed in reasons.
2. **What failed, and why?** The default `run(tasks, candidate)` evaluates nothing: the spec's signature has no way to turn a
   candidate into output, and the implementer's fallback (verifier alone) ignores the candidate. It passes for the wrong reason.
3. **Which assumption was wrong?** "A fresh HOME and TANISHI_HOME is isolation." It stops accidental writes to real memory; it does
   not stop a candidate from reading the exam, sharing state between seeds, or seeing the caller's environment.
4. **What should the next agent know?** Read `runs/redteam-AR1-20261009.md` before building AR2-AR4. Eleven strict-xfail proofs
   are in `tests/arena/test_redteam_ar1.py`; remove each marker when you fix its break. RT-1 and RT-2 block the Frontier and
   Sealed tiers. Nothing in the product code was changed by this run.
