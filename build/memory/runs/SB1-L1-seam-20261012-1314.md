# SB1 · SB1-L1 seam repair (2026-10-12), implementation agent

Branch `agent/hardening/sb1`, after merging main (L1). Eight tests in `tests/compiler` failed with
"test could not run: TypeError".

## The TypeError (seen before any change)

`run_skill_test` catches the exception and keeps only its type name, so I called `passes._run_driver` directly from a
throwaway test (deleted afterwards) and replayed L1's line:

```
Traceback (most recent call last):
  File ".../tests/compiler/test_zz_tmp_repro.py", line 12, in test_repro
    returncode, stdout = p._run_driver(req, 10)  # what run_skill_test does
    ^^^^^^^^^^^^^^^^^^
TypeError: cannot unpack non-iterable PythonResult object
```

The call itself was fine: `run_python(_DRIVER, stdin=<str>, timeout_s=20.0)` ran in Docker and returned
`PythonResult(returncode=0, stdout='\nx 1\n', stderr='', timed_out=False)`. The bug was the return shape. L1 had read
SB1's interface as returning `-> (returncode, stdout)` (`open-problems/L1-repair-conflicts.md` item 2), and SB1 shipped a
4-field frozen dataclass.

## What changed

**Sandbox side** (`tanishi/sandbox/core.py`, commit 86ed25b):
- `PythonResult.__iter__` yields `(returncode, stdout)`, so L1's unpacking works. The fields `returncode`, `stdout`,
  `stderr` (text, clipped to 64 KB) and `timed_out` stay as they were.
- `script` takes str or bytes. `stdin` takes str, bytes or None and defaults to `b""`. `timeout_s` is int or float
  (bool is refused, as before). It still runs untrusted, with no network, is killed at `timeout_s`, and raises
  `SandboxUnavailable` on macOS without Docker.
- `tests/sandbox/test_sandbox_impl.py::test_run_python_needs_source_text_and_a_finite_timeout` is SB1's own
  implementer test, not the exam or the red-team file. It asserted that bytes were refused, which contradicts this
  round's rule. Now it asserts that a list script and an int stdin raise TypeError. No exam or red-team assertion
  was touched.

**L1 side** (`tanishi/compiler/passes.py`, commit 8504a27). The call site is unchanged. The only change is the
human-decided fallback:
- `run_skill_test(..., *, from_template=False)`. `_pass4_check` passes `from_template=True`.
- In `_run_driver`, `SandboxUnavailable` with `from_template=True` writes one `skill_test_unsandboxed {reason}` event
  and runs the old isolated interpreter. Any other error, or any code not marked as template code, is still a refusal.
- The rule is written into decisions 0025 §9 and 0026 (seam-round bullet). Known bugs were updated in
  `known-bugs/l1-compiler-limits.md`.

**New test** `tests/compiler/test_skill_test_sandbox_seam.py`. These are seam tests the human asked for; they are not
an exam.
- The skill test goes through `tanishi.sandbox.run_python` (checked with a spy). It cannot read a host file outside
  its scratch, while the same test passes unsandboxed (control).
- pass 4 lands through the real sandbox with no `skill_test_unsandboxed` event.
- The fallback logs its reason for template code, never applies to other code, and other sandbox errors are still
  refusals.
- `run_python` accepts str and bytes, an int or float timeout, and works with stdin left out.

## The four questions

1. **What did we learn?** A harness that collapses exceptions to their type name hides seam bugs. The fix was one
   line, but finding it took a direct call.
2. **What failed, and why?** Two agents built against a guessed interface. L1 guessed a tuple, SB1 specified a
   dataclass, and no test exercised the real pair until the merge.
3. **Which assumption was wrong?** That "the signature" was the risk. The arguments matched; the return type did not.
4. **What should the next agent know?** `PythonResult` unpacks as a 2-tuple on purpose; do not remove `__iter__`
   without changing `run_skill_test`. Only `_pass4_check` may pass `from_template=True`.

## Still open

- A sandboxed timeout reports "test failed", not "test timed out" (both refuse; known-bugs/l1-compiler-limits.md).
- `from_template=True` is trusted on the caller's word. If a future pass feeds model-written code through
  `_pass4_check`, it would inherit the fallback. A stronger check would regenerate the template and compare.
- On a Mac without Docker, pass 4 runs unsandboxed (logged). That is by design, per the human's decision.
