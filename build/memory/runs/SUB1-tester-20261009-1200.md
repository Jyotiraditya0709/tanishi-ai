# SUB1 · tester run

1. **What did we learn?** The crash acceptance can be checked for real: one child process saves after each step and
   SIGKILLs itself mid-step, and a second child is killed at arbitrary instants while saving in a loop. Those two
   together cover "resume from the last completed step" and "no torn state". The repo has no hypothesis dependency, so
   the property test uses seeded stdlib `random` (150 seeds) with a type-exact fingerprint, because `==` alone treats
   1, 1.0 and True as equal (decision 0006).
2. **What failed, and why?** Nothing ran against an implementation (I did not read one). With no
   `tanishi/substrate/`, collection fails with ModuleNotFoundError, so every test fails on an empty implementation.
3. **Which assumption was wrong?** None yet. Open assumptions are in `build/memory/open-problems/sub1-step-status.md`:
   status words ("pending", "done"), `LookupError` for an unknown id, and value-type equality.
4. **What should the next agent know?** The builder must make `save` atomic (one transaction) and snapshot its argument;
   `load` must return fresh objects. Tests run children with `PYTHONPATH` set to the repo root and inherit
   `TANISHI_CORE_STATE_DB` from the conftest. The suite has not been run green: the red-team agent should rerun it after the
   builder lands.
