# AR1 · implementer · 2026-10-09 17:21

1. **What did we learn?** Running every (task, seed) in its own spawned process makes all the acceptance lines easier.
   A timeout can really stop the attempt. The caller's environment is never touched, so it never needs restoring. Isolation
   is just "set env in the child". Spawn is cheap enough: the arena suite (106 tests, ~150 attempts) runs in about 16 s.
   Redirecting only `TANISHI_HOME` is not enough. Legacy tools write to `Path.home()/.tanishi` and `data/db.sqlite` relative to cwd,
   so the child also gets a temp `HOME`, a temp cwd, and has the legacy path variables unset.
2. **What failed, and why?** The first runner commit silently left out `runner.py`, because `.gitignore` has `runner.*`
   (see `known-bugs/gitignore-runner-pattern.md`). One exam test cannot run because of a fixture-call bug
   (`open-problems/AR1-exam-conflicts.md` C1). I made the same `verifier=` double-argument mistake in my own test first.
3. **Which assumption was wrong?** That a background job started by an attempt dies with it. It doesn't. The process group
   must be killed even when the attempt process has already exited normally (test: `test_background_jobs_do_not_outlive_the_attempt`).
4. **What should the next agent know?** The attempt contract is `decisions/0008-arena-attempt-contract.md`. Candidates are not
   resolved from git refs or config ids yet. Pass an `executor` (`open-problems/AR1.md`). Executors and verifiers must be
   importable module-level functions, because attempts are spawned. Out-of-range verifier scores count as 0, not clamped.
   AR1 produces no intelligence of its own, so there is no benchmark. Its evaluation is the failure-scores-zero and isolation tests.
