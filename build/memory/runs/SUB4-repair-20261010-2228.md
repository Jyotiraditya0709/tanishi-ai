# SUB4 · repair run (red team B1, B1b, B3, B4, B6; B7 decided, not built)

1. **What did we learn?** "The row follows every resolution" needs two layers. The read-through in
   `get_capability()` (the human's choice) keeps the router right whatever process resolved. Only a hook in CS5 makes
   the table itself right for a raw SQL reader, which is what the B1 proof does. Putting the cheap `resolved_at >=
   updated_at` test before `json_extract` keeps a fresh read at about 6 ms on 60k ledger rows (about 0.1 µs a row);
   a refresh stays about 100 ms, the red team's 3 µs per tagged row. The evidence count needs no column: keyed by the
   row's own `updated_at`, an in-memory count can never go stale.
2. **What failed, and why?** My first B4 fix checked only for `[REDACTED`. A lone-surrogate tag is stored by CS5 as
   U+FFFD, so `co\udc80de` and `co\udc81de` would still merge. U+FFFD now counts as a redaction mark too.
   Running scratch scripts outside `python -m pytest` needs approval here; a throwaway test file run with `-s`
   (then deleted) worked for the timing.
3. **Which assumption was wrong?** The card said the read-through covers ToolRegistry and every CS5 caller "without a
   hook". It covers the read, not a SQL read of the table, so the B1 proof cannot pass without a hook. The test won:
   I added `predictions.on_resolve()` (after commit, fail open, every CS5 test passes). Written up in
   `open-problems/SUB4-repair-conflicts.md`; the human should confirm the hook stays. Also, an always-on prior for B6
   would have made B7's strict xfail pass, so the Laplace prior applies only below 5.
4. **What should the next agent know?** SUB3: read `get_capability(cap)` and check `.low_evidence` (`evidence < 5`)
   before trusting `.ability`. Never use readings for Arena scoring or promotion until predictions carry a `call_id`
   (decision `0021-self-model.md` point 9, was 0020). `resolve_prediction()` is now plain CS5 `resolve()`: the hook
   registered at import of `tanishi.substrate.uncertainty` does the update. Changed files: `uncertainty.py`, CS5
   `predictions.py` (hook only), the impl tests, and only the B6 xfail mark in the red-team file.
