# Red team · CS2 event log · 2026-10-09

Target: branch `agent/core/cs2` (events.py, brain.py and registry.py wiring). Proving tests: `tests/core_state/test_events_redteam.py`.
Every open break is `xfail(strict=True)`: the suite is green now, and the fix that makes a test pass forces the mark off.
Result: 329 passed, 26 xfailed. The 26 xfails are the 13 findings below (some have several cases: 8 free-text and 7 key-based redaction cases, 2 chain-wipe cases, 2 nesting cases). No protected path touched. I confirmed each structural break fails for the stated reason with `--runxfail`, not by accident.

## Breaks

| # | Sev | Break | Test | Smallest fix |
|---|-----|-------|------|--------------|
| C1 | **High** | **Deleting the tail (or the whole log) and then letting one honest `emit()` run is not detected.** `verify_chain` never checks ids are contiguous. `emit()` takes `max(head, seq)+1`, links to the new head and `sqlite_sequence` catches up, so the gap is invisible. Violates "deleting any row makes verify_chain return the first broken id". | `test_deleting_the_tail_then_emitting_hides_the_deletion`, `..._every_row_...` | In `verify_chain`, require `id_ == last_id + 1` (first id 1); return `(False, last_id + 1)` on a gap. Costs nothing, ids are contiguous by construction (the seq update rolls back with the insert). |
| C2 | **High** (false positive) | **A healthy log is reported tampered while anyone is writing.** `verify_chain` reads rows in one statement and `sqlite_sequence` in another, so an `emit()` between them makes `seq > last_id`. Measured 3 false alarms in 300 verifies with one writer thread. Any monitor that runs verify live will cry wolf and be switched off. | `test_verify_chain_gives_no_false_alarm_while_a_writer_is_active` | Run both reads inside one read transaction (`BEGIN` before the scan, `ROLLBACK` after), so they share a snapshot. |
| E1 | **High** | **Audit evasion by lone surrogate.** `"\ud800"` survives `json.dumps(ensure_ascii=False)` then dies in `.encode("utf-8")`. The wiring fails open, so a tool input or user message containing one is simply not logged. Surrogates reach Python from terminals and files decoded with `surrogateescape`. | `test_lone_surrogate_in_a_payload_is_still_logged` | Make `redact()` replace lone surrogates (`s.encode("utf-8","surrogatepass").decode("utf-8","replace")`), or hash with `errors="surrogatepass"` and store `ensure_ascii=True`. |
| E2 | **High** | **Audit evasion by nesting.** A tool input nested 3000 deep runs the tool but `redact()` raises `RecursionError`, the wiring swallows it, no `tool_call` event exists. Same for any payload over ~1000 levels. | `test_deeply_nested_tool_input_is_still_logged`, `test_deeply_nested_payload_is_logged_not_dropped` | Make `redact()` iterative or depth-capped (replace anything deeper than e.g. 50 with `"[TRUNCATED]"`); the same cap applies to `_jsonable`. |
| E3 | Medium | **Fail-open plus no gap marker.** E1, E2, C3 and a locked/unwritable db all end as one warning line while the action proceeds. The log looks fine and verifies, but it is incomplete. Decision 0008 accepted fail-open; what is missing is any way to see that it happened. | covered by E1/E2/C3 | When `_record` fails, keep a process counter and, on the next success, emit a `log_gap {kind, count, error_type}` event. Cheap and makes holes visible. |
| C3 | Medium | **One unhashed row bricks logging.** A raw INSERT without `hash` (UNIQUE allows many NULLs; the CS1 trigger lets such a row be deleted) makes `emit()` raise `TypeError` on `None + canonical` for ever. With fail-open that is silent. Any future node that writes `events` raw does this by accident. | `test_one_stray_unhashed_row_must_not_stop_all_later_logging` | Choose the head with `WHERE hash IS NOT NULL ORDER BY id DESC`; `verify_chain` keeps reporting the stray row. |
| W1 | Medium (benchmark passes for the wrong reason) | **`task_end.success` is True for failed tasks.** `_think` turns API and Ollama errors into a normal `BrainResponse(model_used="claude (error)")`, so failure analysis in the M1 loop sees success. | `test_task_end_success_is_false_when_the_model_call_failed` | `success = response is not None and not response.model_used.endswith("(error)")`; better, add an explicit `error` field to `BrainResponse` when the brain next changes. |
| W2 | Medium (bad abstraction) | **Events cannot be correlated.** `session_id` is never set; `task_*` and `tool_*` share no id; `tool_call` and `tool_result` share no call id. Two concurrent tasks, or two parallel calls of one tool, interleave and cannot be paired. The M1 loop needs "this task, these tool calls, this failure". | `test_tool_events_can_be_tied_to_their_task_and_to_each_other` | Add `call_id = uuid4().hex` to both tool events; pass the task id through a `contextvars.ContextVar` set in `think()` and add it as `task_id` to tool events (or set `session_id`). |
| R1 | Medium | **Secrets written to the log in free text.** Not caught: `password=hunter2` (value under 8 chars), `SECRET_KEY=...`, `AWS_SECRET_ACCESS_KEY=...`, `private_key=...`, JWTs, `Authorization: Basic ...`, `?token=...`, `scheme://user:pass@host`. | `test_secret_shapes_in_free_text[*]` (8 cases) | Assignment regex: name = `\w*(?:secret\|password\|passwd\|token\|api[_-]?key\|private[_-]?key)\w*`, min value length 1. Add patterns for JWT (`eyJ[\w-]+\.[\w-]+\.[\w-]+`), `Basic <b64>`, URL userinfo and `[?&](token\|key\|sig)=`. |
| R2 | Medium | **Secrets written under secret-looking keys.** Only a non-empty *str* directly under `password`/`api_key`/`secret`... is blanked. A dict, list or number under it, and keys named `token`, `authorization`, `cookie`, `credentials`, are written whole. | `test_secret_values_under_secret_looking_keys[*]` (7 cases) | If the key matches, replace the whole value whatever its type; add `token`, `authorization`, `cookie`, `credential`, `bearer` to `_SECRET_KEY`. |
| P1 | Low-Medium | **Tool input is not clipped** (known gap). A 5 MB `write_file` body is stored whole: 5 000 036 bytes in one row, and every `verify_chain` re-hashes it. A model can bloat the log at will. | `test_tool_input_is_clipped_like_tool_output` | Clip strings inside the input to ~4000 chars after redaction, as for output. |
| T1 | Low | **`since` with a `Z` suffix skips events.** Stored ts is `...00.123456+00:00`; `"...:00Z"` compares greater than any ts within that second (`Z` > `.`), so the since-second loses its events. | `test_since_filter_with_z_suffix_does_not_skip_events_in_that_second` | Parse `since` with `datetime.fromisoformat`, normalise to UTC microsecond ISO, then compare. |

Not fixable by the node, restated so nobody forgets: **no anchor** (known gap). With file access an attacker drops the triggers, rewrites a tail row, rehashes and fixes `sqlite_sequence`, and `verify_chain` passes. C1 only closes the *cheap* version of that. Also `INSERT OR REPLACE` bypasses the delete trigger (REPLACE does not fire it), so the trigger layer is weaker than decision 0007 implies; the chain still catches a non-rehashed edit (held, tested).

## What I tried that held

- Single-byte tamper of every column, row delete mid-chain, row insert, `INSERT OR REPLACE` of a middle row: all caught at the right id.
- 8 threads x 25 emits, each on its own connection: 200 rows, no fork, chain verifies.
- NaN, `object()` and `set` payloads: `emit` raises, nothing written.
- Catastrophic backtracking on 200k spaces after `password`, 20k unterminated private-key headers, `sk-` x100k, `api_key=` x50k, `bearer ` x50k, 1 MB of `a`: all under 2 s.
- Key shapes in `kind`, `actor`, `session_id`: redacted.
- Tool timeout and tool failure still get a `tool_result`; non-str tool output (dict, None, bytes) does not break `execute()`.
- Garbage db file: `emit` raises `DatabaseError`, writes nowhere else.
- Abandoned `iter_events()` generator does not pin the db.
- Performance: `emit()` is about 0.85 ms per call including the reopen and `migrate()` (200 emits in 0.17 s). Not a regression worth caching yet. The real cost is that it is synchronous on the event loop (known gap).
- Protected paths: `git diff main --name-only` shows none touched. No `*.db`, no `.env` in the diff.

## Not tested

- Cross-process contention beyond threads (separate OS processes) and crash-kill mid-commit; SQLite WAL makes both safe in theory, I did not kill a process.
- Real Anthropic error strings containing key fragments (redaction would catch full keys only).
- `stream_think()` is unwired (known gap): streaming chats leave no events.
