# E2 · implementer run, 2026-10-12

Built `tanishi/observability/causal.py` (`verify_gain`, `attribute`, `Attribution.as_dict`, `organ_scores`) against
the tester's exam (96 cases, all pass unchanged) and added `tests/observability/test_causal_eval.py` (evaluation).

1. **What did we learn?** OBS3's `is_real_gain` was already the right judge; E2 is mostly about who runs the arms. Having
   `causal` call `run_fn` itself (shuffled seeds, per-seed shuffled arm order) is what makes "seeded repeats" and
   "randomized interleaving" enforceable instead of a convention. Passenger false-accept is ~0.5%; recall needs ~3-4 sigma.
2. **What failed, and why?** Nothing in the exam. Ruff's B023 flagged closures over loop variables in the eval; bound
   them as defaults. Running ad-hoc scripts from /tmp needs approval in this setup, so the evaluation lives as a test.
3. **Which assumption was wrong?** I expected `test_gene_gain_inside_noise_is_rejected` to be fragile, since its noise
   table fills in call order and my shuffle differs from the tester's reference. It passes; the 0.3 gene is well clear.
4. **What should the next agent know?** Use `causal.attribute`, not `attribution.ablate`, for new code: it gives each
   gene a verdict. Feed `Attribution.as_dict()` into `genome.record_version(attribution=...)`. Organ scores sum real
   gains (decision 0028). Interaction double-credit is still open (known-bugs/e2-causal-limits.md).
