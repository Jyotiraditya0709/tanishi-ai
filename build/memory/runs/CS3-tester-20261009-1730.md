## 1. What did we learn?
- The CS3 interface takes no connection, so the tests must run on the default Core State db from `TANISHI_CORE_STATE_DB`. `tests/conftest.py` already points it at a temp file.
- CS2 (`emit()`) is not merged, so "emits a belief_conflict event" is tested as a row in `events` with `kind = 'belief_conflict'`, nothing about hashes.
- The legacy schemas (`core_memory(key, value, updated_at)`, `memories(id, content, ...)`) are in `tanishi/memory/manager.py`; the importer fixtures copy them.

## 2. What failed, and why?
- Nothing ran green or red yet: there is no implementation to run against. First real run is the implementer's.
- I dropped hypothesis (not a dependency, CLAUDE.md says a new one needs a PR line). The property test is seeded `random` over 8 histories: nothing deleted, confidence in [0,1], contested iff a live peer disagrees, `contradictions()` equals that peer set.

## 3. Which assumption was wrong?
None disproved yet. Assumptions the spec does not settle, which the tests pin down. If the implementer disagrees, ask the human and change the test, not the spec silently:
- **Contested counts as live.** `contradictions(b)` after the conflict still returns the other side, so "both active" means "active or contested". A belief with status `retired`-like (anything not active/contested) is excluded.
- Retire's status word is not fixed; the test only requires it is non-empty and not active/contested. The `reason` must be stored somewhere in the db (evidence note, event payload, ...).
- Third contradicting belief contests all three and emits at least one more event (not exactly one per pair).
- The conflict event payload is valid JSON containing both belief ids.
- `find(text=...)` is a literal substring match over subject/predicate/object (`%` and `_` are not wildcards).
- Confidence NaN: refuse (ValueError/TypeError) or map into [0,1]; never store it. +/-inf clamp.
- Missing/blank/whitespace source raises ValueError or TypeError and stores nothing.
- Importer CLI: `python scripts/import_legacy_memory.py <path>`, exit 0 on success, non-zero on a missing path or no argument, never modifies or creates the legacy file, one belief per `core_memory` row and per `memories` row, all with source `legacy`, second run adds nothing (and emits no events), a later run adds only new rows.
- Not tested because the spec is silent: `retire()` of an unknown id, `find()` with no arguments, whether duplicate identical beliefs merge, what retiring one of a contested pair does to the other's status.
