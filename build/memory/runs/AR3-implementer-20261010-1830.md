1. **What did we learn?** The leak the tester flagged is real: AR1 `run()` writes `task_id` and `reason` into the caller's
   Core State. Pointing `run()` at a throwaway db (an env swap around the call) closes it without changing AR1.
2. **What failed, and why?** Nothing failed. One trap was avoided: re-raising a load error inside `except` keeps the
   original error, which quotes the YAML, as `__context__`. The refusal is raised outside the handler, so there is no chain.
3. **Which assumption was wrong?** That mode bits can meet "the agent OS user cannot read". They only keep out *other*
   users. The real guarantee is running the service as its own OS user, which is why there is a CLI.
4. **What should the next agent know?** AR4 should reuse the same store checks and the HMAC hash. The human still has to
   create the service user and the sudo rule. Red-team targets: same-user deployment, the executor importing the
   verifier module, thread-safety of the env swap, and deleting `.salt` to re-key the hashes.
