1. **What did we learn?** The exam's pinned surface fit the dependencies with no dispute: CS5's Brier score is the
   surprise, CS3's `evidence_event_id` is the evidence link, CS2's `emit()` does the redaction. The landing law is
   simplest as one function with an ordered list of gates, where any exception is a refusal. The prediction id is a
   natural attempt identity, so "record once" needs no new field on Experience.
2. **What failed, and why?** Nothing failed against the exam (46/46 on the first run; full suite 2242 passed). Ruff
   flagged the exam's import order, because `tanishi.compiler` did not exist when it was written (known-bugs/l1-compiler-limits.md).
3. **Which assumption was wrong?** That pass 3's evidence could be the experience event id inside the payload: the exam
   calls `run(exp)` on an unrecorded experience, so the payload carries step-level evidence (`{step, tool, ok}`) that the
   check verifies against the experience, and the compiler adds the event link when it lands.
