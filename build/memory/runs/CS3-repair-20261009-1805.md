## 1. What did we learn?
- `emit()` opens its own connection and takes `BEGIN IMMEDIATE`. Calling it inside a belief transaction would block on our
  own write lock for the 5 s busy timeout and then fail. So belief events are emitted after commit, and the two are not atomic.
- The exam inserts unhashed rows into `events` (`add_event`). After one of those, `emit()` cannot chain (`None + str`), so
  every later belief event fails. CS3 has to fail open to pass the exam; the gap file records the missed writes.
- A SQLite function registered per connection (`belief_key`) gives Unicode-correct normalised matching with no migration.

## 2. What failed, and why?
- R5 dedupe. Built, then removed: every seed of the exam's `test_random_history_invariants` failed because it counts one
  row per `add_belief` call. The version I tried, in `_add` after the `skip_existing` check:
  look up `SELECT ... WHERE belief_key(subject)=? AND belief_key(predicate)=? AND belief_key(object)=? AND status IN live`,
  and if found, link the evidence to it, commit and return it.
- Loading the importer script with `importlib` in a test failed until the module was put in `sys.modules`: dataclasses look up
  their module while the class is built (with `from __future__ import annotations`).

## 3. Which assumption was wrong?
- That the retire reason could go in an evidence row tied to the belief. The exam pins the belief's evidence count across
  `retire()`. The row now has `belief_id` NULL and points at the retire event; `evidence_for()` follows the event.
- That "refuses an unknown id" meant raising. The red-team test asserts `[]`, so `contradictions()` returns `[]`.
