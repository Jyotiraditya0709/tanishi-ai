# Build memory

What the builder organization has learned. Every agent reads the parts that touch its node before starting,
and writes back before finishing. This is a primitive Tanishi building Tanishi.

| Folder | What goes in it |
| --- | --- |
| architecture/ | The frozen map and the constitution, for quick reference |
| decisions/ | Numbered decisions every agent must respect (`NNNN-short-name.md`) |
| failed-approaches/ | What was tried, why it failed, and what not to repeat |
| known-bugs/ | Bugs found and not yet fixed, with where they live |
| open-problems/ | Questions nobody has answered yet, and specs that turned out wrong |
| research/ | Findings per node: what to copy, what to avoid, with links |
| benchmarks/ | Baselines and benchmark results worth keeping |
| performance/ | Speed and resource measurements on the MacBook |
| agent-performance/ | Builder Arena scores per model and role |
| runs/ | One file per agent run: the four after-task answers |

The four after-task questions: What did we learn? What failed, and why? Which assumption was wrong? What should the next agent know?
