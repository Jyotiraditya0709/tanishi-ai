# CS5 · red-team breaks (2026-10-09, repaired the same day)

Details, fixes and the design points are in `runs/redteam-CS5-20261009.md`. Proofs: `tests/core_state/test_predictions_redteam.py`.
Repair notes: `runs/CS5-repair-20261009-2207.md`, conflicts in `open-problems/CS5-repair-conflicts.md`.

- [x] R1 Medium: user denials are scored as tool failures and lower the tool's forecast. *Fixed: only a call whose
  handler ran is scored; a denial or raising approval callback leaves the prediction unresolved, and a tool that
  needs approval with no callback is not predicted.*
- [x] R2 Medium: an event-log outage is scored as tool failures for every tool. *Fixed: prediction left unresolved.*
- [x] R3 Low: unknown tool names enter the ledger and `calibration("tool:")`. *Fixed: not predicted.*
- [x] R4 Low: one resolved row with a non-object `actual`/`expected` breaks `tool_forecast` and `calibration` for all.
  *Fixed: such rows are skipped.* (`resolve()` of a row whose stored `expected` is a non-object still raises for that
  one row; it needs a raw write and harms nobody else.)
- [x] R6 Low: `unresolved_older_than` raises for NaN, inf, huge `hours`. *Fixed as the test requires (returns `[]`),
  not with the ValueError the card asked for: see `open-problems/CS5-repair-conflicts.md`.*
- [x] R7 Low (perf): no index on `predictions`. *Fixed: migration 0003 `predictions_about_resolved`. Breaks three CS4
  builder tests that pin schema version 2: see `open-problems/CS5-repair-conflicts.md`.* `calibration()` still
  scans (its `substr` prefix match cannot use the index), and so does the stale helper; both are rare.
- [ ] Design: nothing proves a prediction was written before the action; do not use `calibration()` as an Arena score
  until predictions carry a `call_id` that matches a `tool_call` event. See `open-problems/CS5.md`.
- [ ] Design: four events per tool call (`prediction`, `tool_call`, `tool_result`, `prediction_resolved`).
- [ ] Design: calls that never ran leave unresolved predictions that the stale helper lists after 24 h; a `void`
  state would tell them apart from forgotten ones (needs a migration).
